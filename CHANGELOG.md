# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added

- **`hail_scan_table(path)`** (`src/hail_table_scanner.hpp` /
  `src/hail_table_scanner.cpp`): DuckDB table function reading Hail `.ht`
  directories directly, without a JVM, Spark, or Python Hail package. The
  implementation uses real HailTable metadata paths, nested `_bufferSpec`
  codec-chain resolution, and the per-row continuation-flag protocol verified
  against production Pan-UKBB HailTable data.
  - Bind phase parses `rows/metadata.json.gz` `_codecSpec._vType` and
    `_codecSpec._eType` strings into the DuckDB output schema, with Hail
    `Array`/`Struct` becoming DuckDB `LIST`/`STRUCT` and `Locus(GENOME)`
    becoming `STRUCT(contig VARCHAR, position INTEGER)`.
  - Scan phase decodes row partitions through a `BlockDecoder` abstraction.
    `ZstdBlockDecoder` handles `ZstdBlockBufferSpec`; `Lz4BlockDecoder` handles
    both `LZ4HCBlockBufferSpec` and `LZ4FastBlockBufferSpec`.
  - Recursive missing-bit handling supports optional struct fields and optional
    array elements. `hail_scan_table` does not perform liftover; loci are
    returned in the reference genome encoded by the source table.
- **Hail type parser** (`src/hail_type_parser.hpp` /
  `src/hail_type_parser.cpp`): parses Hail `VType` and `EType` strings,
  including requiredness markers at any nesting level, into typed trees used by
  the HailTable bind and scan phases.
- **`hail_debug_etype(str)` / `hail_debug_vtype(str)`** scalar functions:
  round-trip testing helpers for the type-string parser.
- **Synthetic HailTable test fixtures** generated by
  `scripts/generate_hailtable_fixture.py`, including Zstd, LZ4HC, LZ4Fast,
  unknown-codec, optional top-level field, and optional-array-element cases.
- **`test/sql/hail_type_parser.test`** and **`test/sql/hail_table.test`**:
  SQLLogicTest coverage for the parser and `hail_scan_table` behavior.
- **`ZstdBlockDecoder`** (`src/hail_codec.hpp` / `src/hail_codec.cpp`): streaming
  decoder for the Hail codec stack used by HailTable part files.  Reads
  `StreamBlockBufferSpec` outer frames and `ZstdBlockBufferSpec` inner frames on
  top of DuckDB's VFS `FileHandle`, transparently supporting local, S3, GCS and
  HTTP backends with partial-read retry logic.
  - `read_byte()` — single byte; maintains eager `eof()` state
  - `read_leb128_u32()` / `read_leb128_u64()` — unsigned LEB128 (Hail
    convention, not zigzag); overflow-guarded at 5 / 10 bytes
  - `read_float()` / `read_double()` — raw IEEE 754 via `memcpy`
  - `read_bytes()` / `skip_bytes()` — bulk operations with cross-block boundary
    support
  - Uses `duckdb_zstd::ZSTD_decompress` from DuckDB's bundled zstd — no new
    external dependency
- **SQL test helpers** registered as DuckDB table functions:
  - `hail_zstd_info(path)` → `(frame_idx INTEGER, decomp_size INTEGER)`:
    inspects raw stream frames and returns the decompressed size per frame
  - `hail_leb128_u32(path)` / `hail_leb128_u64(path)`: count-prefixed LEB128
    round-trip readers for unit testing
- **Test data** under `test/`:
  - `test/variant_indices.ht/rows/parts/part-00000-dc70bdc7-fa3a-4c4a-b60f-324b0e34b4d6`:
    synthetic single-frame file with `decomp_size = 30145`
  - `test/codec/leb128_u32.bin` / `test/codec/leb128_u64.bin`: exact-fit
    encoded files for LEB128 round-trip verification (EOF after last value)
- **`test/sql/hail_codec.test`**: SQLLogicTest suite covering frame metadata,
  LEB128 u32/u64 round-trips (including boundary values such as `UINT32_MAX` and
  `UINT64_MAX`), and EOF behaviour

### Known gaps

- Uncompressed HailTable codecs are not implemented; supported table codecs are
  `ZstdBlockBufferSpec`, `LZ4HCBlockBufferSpec`, and `LZ4FastBlockBufferSpec`.
- `hail_scan_table` reads the row component only. Hail globals and key-index
  structures are ignored because full sequential scans do not need them.
